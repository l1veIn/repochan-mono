# AI 生图驱动的网页构成工艺

> 状态：METHODOLOGY（从 dogfood 实践中提炼的设计方法论）
> 背景：RepoChan 狗粮站 hero 经过多轮迭代（手工拼接 → screenshot-to-code → L1L2 分层 → L1L2 合成），总结出了一套基于 AI 生图的网页 section 构成方法论。

---

## 一、核心原则：留白即接口

传统网页开发中，开发者用 CSS/HTML 精确控制每个像素的位置。AI 生图驱动的网页开发中，**开发者通过 prompt 控制留白的位置和形状，让 AI 在指定区域"不画东西"，然后 HTML 元素填入这些留白区域**。

留白 = AI 生图与 HTML 之间的接口。

留白越多 → HTML 控制力越强、动效空间越大、可维护性越高。
留白越少 → 视觉融合度越高、AI 的设计感越强、但后期修改越难。

**关键不是"AI 画得好不好"，而是"留白留得准不准"。**

---

## 二、四种合成策略

### 策略 A：完整设计稿（L1+L2+L3+L4 全合成）

```
AI 生成 → 完整 section 视觉（含文字、按钮、导航）
↓
screenshot-to-code 工具 → HTML/Tailwind 代码
↓
人工/agent 微调
```

**画师生成什么**：背景 + 角色 + 艺术化文字 + UI 元素，一张完整的网页截图。

**HTML 填什么**：全部由 screenshot-to-code 转，不需要手工留白。

**优点**：
- 视觉冲击力最强——画师掌控一切
- 最快出效果——一张图就是一个 section

**缺点**：
- 文字是图片，不可选中/搜索/翻译
- 改文字需要重新生图
- 无法加动效（全是一张图）
- screenshot-to-code 的转换质量决定成败

**适用场景**：初版快速验证、视觉方向探索、不需要交互的展示页。

**代表**：`hero-v4-manga.png`

**prompt 模式**：详细描述每个元素的位置、内容、样式，让 AI 做完整设计。

---

### 策略 B：L1L2+L3 合成，L4 留白（文字融入画面，按钮留空）

```
AI 生成 → 背景 + 角色 + 艺术化标题文字（按钮/链接区域留白）
↓
HTML 填入 → L4 按钮、导航、链接（放在 AI 留出的空白区域）
```

**画师生成什么**：背景 + 角色 + **艺术化的大标题文字**（文字太艺术了 HTML 难以复刻的，干脆画在图里），但在按钮、CTA、导航的位置**留出干净的空白**。

**HTML 填什么**：按钮、CTA 链接、导航栏——这些需要交互的元素。

**优点**：
- 标题可以极度艺术化（AI 直接画在图里，不用考虑 HTML 字体限制）
- 按钮可交互（hover、点击）
- 视觉和控制力的平衡点

**缺点**：
- 标题文字不可选中/搜索
- 留白位置需要精确——画师要理解"这里不画东西"
- 按钮 hover 效果和图片背景的视觉协调需要调

**适用场景**：需要大胆艺术化标题、但 CTA 必须可点击的落地页 hero。

**代表**：`ord-section-hero-002`（超大字体与角色互动，右下角留 CTA 位置）

**prompt 模式**：描述标题内容和艺术化方向，**明确指定按钮/CTA 区域"留空，保持背景色，不画任何元素"**。

---

### 策略 C：L1L2 合成，L3L4 留白（当前 hero 采用）

```
AI 生成 → 背景 + 角色合成图（文字和 UI 区域大面积留白）
↓
HTML 填入 → L3 标题/副标题/stats + L4 按钮/导航
```

**画师生成什么**：背景 + 角色已经合成在一起的完整图，**一侧大面积留白**（纯背景色/氛围，无内容）。

**HTML 填什么**：全部文字和 UI 元素，覆盖在留白区域。

**优点**：
- 角色和背景完美融合（无抠图残留）
- 文字完全可选中/搜索/翻译/i18n
- 所有 UI 元素可交互
- 动效空间最大（文字渐入、按钮 hover、视差都独立可控）

**缺点**：
- 文字受限于 web 字体（无法像策略 B 那样艺术化）
- 留白区域的设计感依赖画师——如果留白太"空"，HTML 文字填上去会显得突兀

**适用场景**：需要 i18n、SEO、可维护性、动效的生产级网站。

**代表**：`hero-composite-4k.png`（v4 去掉文字/UI，左侧暗色区域留给 HTML）

**prompt 模式**：
- **生成完整设计稿**（策略 A），然后用"remove text and UI elements"拆出 L1L2 合成图
- 或直接描述"左侧 45% 保持暗色空旷，右侧 55% 是角色+背景"

**两种生成路径**：
1. **先 A 后 C**：先生成完整设计稿（含文字），再 edit 去掉文字 → `hero-composite-4k.png` 就是这么做的
2. **直接 C**：生成时就说"左侧留空给文字" → 更难控制，AI 可能不理解"留空"

**推荐路径 1**——先让画师做完整设计（构图最自然），再去除文字层。去除文字的 prompt 要**简单直接**：

```
Remove all elements except the character and the background. Keep the
character and background completely unchanged. Remove all text, UI
elements, buttons, labels, navigation, floating code snippets, and
decorative symbols.
```

经验教训：
- 不要试图解释"什么是背景什么是 UI"——AI 会困惑
- 简单列出要删除的东西 + 强调保留角色和背景
- "floating code snippets, and decorative symbols" 要明确列入删除

---

### 策略 D：L1L2 分层（背景和角色独立）

```
AI 生成 L1 → 纯背景（无角色、无文字）
AI 生成 L2 → 纯角色（matte 底 → chroma-key 抠透明 PNG）
↓
HTML/CSS 叠加 → L1 底图 + L2 角色 + L3 文字 + L4 UI
```

**画师生成什么**：两张独立的图——一张纯背景，一张纯角色（matte 底）。

**HTML 填什么**：全部文字和 UI，加角色透明 PNG 叠在背景上。

**优点**：
- 最大动效自由度——背景、角色、文字、UI 四层独立
- 角色可以做浮动/呼吸/视差
- 背景可以做渐变流动
- i18n / SEO 完全可控

**缺点**：
- **角色抠图是瓶颈**——发梢、半透明材质（罩袍）、毛发在 chroma-key 下有残留
- 两张图分别生成，构图对齐需要人工保证
- 生成成本翻倍（两张图）

**适用场景**：需要复杂动效、角色需要独立运动的场景。

**代表**：`hero-bg.png` + `hero-character.png`（尝试过，发梢残留问题导致放弃）

**当前结论**：AI 生图的半透明细节（头发、纱质材料）对 chroma-key 提取构成挑战。在 matte 技术（chroma + spill suppression + dual-background）进一步成熟前，**策略 C（L1L2 合成）是视觉效果和工程可控性的最佳平衡点**。

## 三、留白工艺要点

### 留白位置

| Section 类型 | 推荐留白位置 |
|-------------|-------------|
| Hero（角色在右） | 左侧 40-50% 留白 |
| Hero（角色在左） | 右侧 40-50% 留白 |
| Hero（角色居中） | 上下留白，或角色两侧对称留白 |
| Features | 每个 feature 卡片内部留白（角色表情做图标，文字区域留空） |
| CTA | 中央留白，背景+角色做环绕 |

### 留白形状

- **矩形留白**：最简单，AI 最容易理解。"left side dark and empty"
- **L 型留白**：角色在右下角，留白是左+上。需要更精确描述。
- **负空间留白**：角色姿态自然形成的空白区域。最难控制，但视觉最自然。

### 留白背景

留白区域不应该是一片死寂的纯色——它应该有**和主画面一致的氛围**：
- 暗色背景 + 极淡纹理（hero-composite 的做法）
- 角色的辉光渗透到留白区域（cyan glow bleeding into the text zone）
- 留白区域有微妙的渐变，不是 flat color

这确保 HTML 文字叠上去时不会显得"贴上去的"，而是"长在画面里的"。

## 四、质量与尺寸

| 用途 | 推荐尺寸 | 质量 |
|------|---------|------|
| Hero 背景合成图（策略 C/D） | 3840×2160 (4K) | high |
| Section 设计稿（策略 A/B） | 1536×1024 或 3840×2160 | high |
| 纹理（四方连续） | 768×768 | auto |
| Chibi/icon（网格切片） | 1024×1024 | auto |
| Favicon/icon-single | 1024×1024 → resize | auto |

L1L2 合成图是全屏背景，4K 是底线——低于 4K 在高分屏上会模糊。

## 五、决策树

```
需要 i18n / SEO / 文字可选中？
├─ 否 → 策略 A（完整设计稿 → screenshot-to-code）
└─ 是 → 需要复杂动效（角色独立运动）？
        ├─ 是 → 策略 D（L1L2 分层）—— 注意抠图质量风险
        └─ 否 → 标题需要极度艺术化（超现实字体/角色与文字互动）？
                ├─ 是 → 策略 B（L1L2+L3 合成，L4 留白）
                └─ 否 → 策略 C（L1L2 合成，L3L4 留白）—— 推荐默认
```

**推荐默认：策略 C**。它是视觉效果和工程可控性的最佳平衡：
- 角色和背景完美融合（不需要抠图）
- 文字/UI 全部 HTML（i18n/SEO/动效全可控）
- 4K quality high 确保精细度
- 生成路径成熟（完整设计稿 → 去除文字层）

# Plan: 抽取 `@repochan/starters` 包 + 扩展 order references 支持 file 引用

## 背景

当前 `repochan-page/` 同时是模板源(CLI 默认从这里读)和 dogfood 实例(装着真实资产),混合状态。抽成 `@repochan/starters` 独立包,模板可按风格命名(`constructivist` 是第一个),并为后续"starter 默认资产作为角色迁移参考图"铺路。

同时,为了让 starter 的默认资产能作为参考图传进 order,需要扩展 `OrderReference`,从「只接受 orderId」变成「orderId 或文件路径」的 discriminated union。

## 第三部分:order references 扩展(支持 file 引用)

把 `OrderReference` 从固定形状改为 discriminated union,让 starter 参考图能以 `{type:"file", path:...}` 形式进 order。**向后兼容**:现有 `{orderId, role}`(无 type)继续被当作 order 引用。

### 3.1 `packages/core/src/types.ts:10-18`

```ts
export type OrderReference =
  | { type?: "order"; orderId: string; versionId?: string; role: ReferenceRole }
  | { type: "file"; path: string; role: ReferenceRole };
```
> `type` 在 order 变体里可选 → 现有无 type 的 `{orderId, role}` 自动兼容。

### 3.2 `packages/core/src/schemas/index.ts:196-200`

`OrderReferenceSchema` 改为 TypeBox `Type.Union([orderVariant, fileVariant])`,order 变体的 `type` 为 Optional。

### 3.3 `packages/core/src/utils/index.ts:79-98`(`normalizeReference`)

按 discriminator 分支:order 变体走 `validateOrderId`;file 变体校验 `path` 非空字符串(路径存在性校验留给 resolver)。

### 3.4 `packages/core/src/entities/orders.ts:483-509`(`resolveOrderReferences`)

加 file 分支:`path.resolve(projectRoot, ref.path)` → 存在性检查 → 作为 `files: [abs]` 返回。返回类型的 `orderId`/`versionId` 改为可选(file 引用没有这两个值)。

### 3.5 运行 core 测试

`pnpm --filter @repochan/core test`(invariant #1:协议/业务规则改动必跑)。
